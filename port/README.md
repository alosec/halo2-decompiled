# Native port (experimental)

This directory is the clean, open-source host/runtime track for running the recovered Halo 2 code on modern systems. It is separate from the byte-matching Xbox build. It never embeds or installs game data, an XBE, an Xbox SDK, or other proprietary material.

The first product milestone is an authentic loading main menu on Apple Silicon using files supplied by the user from the supported retail disc. The current checkpoint loads the authentic main-menu tag index through recovered cache code and fully links an eighty-seven-unit/slice Microsoft-ABI UI guest image with freestanding CRT support. Its constructor-aware startup initializes the recovered UI manager, leaves an authentic press-start screen in a recovered window channel, and executes recovered update/render traversal only after authentic tag state exists. SDL now draws the resulting immediate and interface quad geometry and decodes the recovered format-16/DXT5 bitmap references directly from the user's map. A finite frame capture visibly produced the authentic Halo 2 logo and recovered localized `PRESS START TO CONTINUE` string using the original retail font glyphs. Enter/Space and gamepad South/Start now activate the recovered press-start handler and advance into the authentic four-way `CHOOSE PROFILE` screen. The activated SDL keyboard/gamepad source is represented as controller 0, so the chooser authentically changes that panel to `PRESS A TO JOIN`; the other slots remain disconnected. Escape or gamepad East cancels this native-offline fallback through the recovered return-to-press-start callback. The connected chooser slot now opens the recovered profile selector, whose focused `CREATE NEW PROFILE` item traverses its retail handler and opens the genuine recovered type-1 profile-name keyboard with an available `HaloNNNN` name. Durable profiles also appear as recovered selector rows. Enter/gamepad South and deterministic `--finish-frame` complete the recovered default name, but host text entry and directional keyboard navigation are not connected yet. Recovered list-family setup now attaches, assigns, focuses, frames, and disposes its embedded rows through the retail virtual slots, so profile completion reaches a visibly authentic one-user main menu with `CAMPAIGN`, `XBOX LIVE`, `SPLIT SCREEN`, `SYSTEM LINK`, and `SETTINGS`. Arrow keys and gamepad D-pad Up/Down now traverse those rows through the recovered list-step and focus paths. Activating the focused `CAMPAIGN` row now follows its recovered handler into the authentic `CAMPAIGN OPTIONS` screen, whose durable no-save profile state truthfully shows `NEW CAMPAIGN` and `COOPERATIVE`; the same recovered arrow/D-pad path traverses those rows and updates their descriptions, while B/Escape follows the recovered screen close path back to the one-user menu. Deeper Campaign actions and the other main-menu destinations remain unavailable, so this is not yet a finished interactive menu.

## Local build

Requirements on macOS:

```sh
brew install cmake ninja openssl@3 sdl3
cmake -S . -B build/native -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DOPENSSL_ROOT_DIR="$(brew --prefix openssl@3)"
cmake --build build/native
ctest --test-dir build/native --output-on-failure
```

Point the host at an ignored directory containing files extracted from your own supported retail disc:

```sh
build/native/port/halo2-port --headless --data-root orig/game
build/native/port/halo2-port --headless --data-root orig/game \
  --guest-image build/native/port/main-menu-core.elf \
  --guest-entry h2_main_menu_guest_bootstrap
build/native/port/halo2-port --data-root orig/game
```

`H2_DATA_ROOT` may be used instead of `--data-root`. `--profile-root PATH` selects the private native profile directory; it defaults to a sibling `profiles` directory beside the supplied game-data root. The optional `--guest-image PATH` loads a completed AArch64 guest ELF into the same arena after the retail XBE state, applies its final protections, configures host ownership of the user's `mainmenu.map`, and patches the standard native services. `--guest-entry SYMBOL` explicitly invokes a zero-argument entry on a dedicated guest-address stack and requires `--guest-image`; the checked-in bootstrap runs its static constructor table, loads the authentic tag index through recovered cache code, initializes offline profile/save and UI state, constructs the recovered press-start screen, and verifies that a screen is present. With the complete guest bootstrap, the graphical command repeatedly executes recovered UI frames, decodes supported retail textures from the user-owned map, and draws the resulting geometry through SDL; without a guest image it remains a diagnostic window. The host draws recovered text from the user's original retail font files, but full controller/navigation, persistence, audio, and renderer ownership are incomplete, so this must not yet be presented as a finished menu. `--frames COUNT` provides a finite graphical acceptance run, `--press-start-frame COUNT` injects one deterministic press-start activation, `--accept-frame COUNT` accepts the connected chooser slot into the recovered profile selector, `--select-frame COUNT` activates its Create New item, `--finish-frame COUNT` completes the generated profile name, `--menu-accept-frame COUNT` activates the focused main-menu row after profile completion, `--down-frame COUNT` and a later `--up-frame COUNT` require recovered main-menu selection steps, `--cancel-frame COUNT` injects a later cancellation, and `--screenshot PATH.bmp` may accompany the run for local visual verification. Such captures are derived from the user's retail data and must not be committed or distributed.

## Architecture

The port uses two cooperating layers:

1. **Guest engine image.** Recovered Halo 2 source retains the original 32-bit layouts, globals, pointer representation, and Microsoft C++ object ABI. C++-heavy units use Clang's 32-bit ARM Microsoft frontend before their LLVM IR is retargeted to ARM ILP32; an LLVM transform then rebases original low virtual addresses into a reserved 4 GB host arena. This follows the proven CC0 address-rebasing approach in `bnunu/halo-ce-universal`, generalized for Halo 2 rather than executing original x86 code.
2. **Native host.** A normal ARM64 process owns SDL3, the window, Metal-backed rendering, audio, input, Darwin files and networking, memory mapping, threads, timing, and calls into the guest image through a versioned ABI.

Port-only substitutions must be selected by build flags or adapter interfaces. They must not alter the source used by the Xbox byte-matching build.

The initial LLVM rebase pass is adapted under CC0 from `bnunu/halo-ce-universal` commit `fd205407a6ac85937d963fd5e2d6ca8deeb26476`. It contains compiler/runtime engineering only. Halo CE compatibility headers derived from debug information are intentionally not imported because this project's provenance rules are stricter. Native compatibility declarations here are written only from public platform facts and the visible needs of recovered Halo 2 source.

## Provenance and legal rules

Follow the repository's `LEGAL.md`, `PROVENANCE.md`, and `CONTRIBUTING.md` without exception. In particular:

- Keep all extracted data below ignored paths such as `orig/`.
- Never commit or distribute an XBE, maps, media, disc image, proprietary SDK material, or generated artifacts containing them.
- Do not use leaked source, symbols, PDBs, linker maps, or confidential material.
- Credit and preserve the licenses of reused open-source platform code.
- Continue verifying matching-engine changes against the supported retail binary when the lawful local toolchain is available. Native-only adapters require their own tests and runtime evidence.
